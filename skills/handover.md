# handover

Write for someone with your task and none of your context.

1. **State the goal** in one sentence — what "done" means, not what you did.
2. **Where it actually stands.** Working, half-working, untouched. Be exact:
   "the write path works, reads are untested" beats "mostly done".
3. **What is verified vs assumed.** Mark every unverified claim as unverified.
4. **The next concrete action**, specific enough to start on without asking.
5. **Dead ends** — what you tried that did not work, and why. This is the most
   valuable part and the one always left out.
6. **Traps**: the thing that will bite them that you only learned by being bitten.

File paths with line numbers. No status theatre — "blocked on a keystore only
the sovereign can make" is useful, "90% complete" is not.

If something durable was learned, record it with `remember` too — a handover is
read once, a memory is read forever.
